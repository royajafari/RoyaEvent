# specs/ — تاریخچه‌ی اجرای فازها

هر فاز از نقشه‌ی راه (`docs/architecture.md` بخش ۱۴) یک فایل `specN.md` جدا داره (`spec0.md` تا `spec3.md` فعلاً). این پوشه جایگزین بخش‌های سنگین «وضعیت فعلی — فاز به فاز» است که قبلاً مستقیم داخل `CLAUDE.md` بودن؛ `CLAUDE.md` فقط ساختار/استک/قراردادهای پایدار رو نگه می‌داره تا سبک بمونه.

## قرارداد هر spec

هر `specN.md` دقیقاً دو بخش اصلی داره:

1. **نتیجه‌ی فازهای قبل (خلاصه)** — چند خط، فقط نتیجه/وضعیت نهایی فازهای `0..N-1`، نه جزئیات کامل دوباره. با لینک به spec همون فاز.
2. **جزئیات کامل همین فاز** — هدف، چیزی که ساخته شد (بک‌اند/فرانت)، تست‌ها، نکات/دام‌های کشف‌شده‌ی مخصوص همین فاز، راستی‌آزمایی، commitهای مرتبط.

هدف این جدابخشی: برای فهمیدن وضعیت فعلی، فقط آخرین `specN.md` رو بخون (خلاصه‌ی قبلی‌ها همون‌جاست)؛ برای کندوکاو تاریخی یک فاز خاص، برو سراغ همون فایل.

## وقتی فاز جدید شروع می‌شه

یک `specN.md` جدید بساز (N = شماره‌ی فاز)، با همون دو بخش بالا. نکات/دام‌هایی که **فقط مخصوص همون فازن** (باگ در سرویس/کامپوننت خاص آن فاز) اینجا می‌رن. نکات/دام‌های **عملیاتی و همیشگی** (مثل مشکل رمزگذاری متن فارسی در Git Bash، یا نیاز به restart دستی uvicorn) به‌جاش در بخش «نکات عملیاتی همیشگی» در `CLAUDE.md` می‌رن، چون به یک فاز خاص محدود نیستن و در هر فاز بعدی هم ممکنه دوباره پیش بیان.
